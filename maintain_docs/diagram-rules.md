# 结构图绘制硬规则

画 architecture / tensor / op 图时**必须**遵守的规则。每一条都来自一次真实的返工，
不是偏好。

给 subagent 的话：动手前整篇读完；写完后逐条对照，并在报告里说明你验证了哪几条、怎么验的。
与你的审美判断冲突时，以这里为准。

- 编号 **R‹n› 一旦分配就不改**，方便在 review 里直接引用。
- 内容正确性（拓扑出处、权重名、未声明的 key、画不出来就不画）不在这里，
  见 [architecture-diagram.md](./architecture-diagram.md) §2 五条铁律。
- 几何引擎的实现约定见同文档 §4；验证手段见 §5、§6。

## 文字

### R1 算子一律深灰底、白色字

不按 `kind` 区分底色。深浅不同的灰会被读成分类，而分类已经由形状表达
（linear 是梯形、reduce 是收束、tensor 是方框）。

**怎么验证**：截图看，所有 op 同一个灰；`arch-nodes.tsx` 里只有一组
`OP_FILL` / `OP_STROKE` / `OP_INK`。

### R2 不用 `·` 作分隔符

任何位置都不用，包括 note、caption、表格、注释。要分隔就用空格、破折号或换行。

**怎么验证**：`grep -n "·" lib/arch components maintain_docs`，应无输出。

### R3 所有字体与正文一致

不给图里的任何文字指定 `--font-mono` 或 `font-sans`。张量形状也用正文字体。

**怎么验证**：`grep -rn "font-mono\|font-sans\|--font-mono" components/arch-* lib/arch`，
应无输出。

### R4 网页上的文字不写长句、不写长段

`note`、`label`、caption、按钮文案都是短句。一行读完，不需要断句理解。

**怎么验证**：跑 `npx tsx tmp/check/labels.tsx`，它会列出所有会显示的字符串，逐条看。

## 图形

### R5 N 份副本最多画 4 张叠片

`STACK_MAX = 4`。256 个专家和 8 个分组都画 4 张，数量写在标签里
（`countSuffix`），不额外画一个"×256"的注记。

**推论（踩过的坑）**：凡是回答"这里有几条轨"的地方，一律走 `sheetsFor(lanes)`，
绝不用原始数量。拿原始数量比较，16 份副本对 4 个实例会被当成一次收束，每条线都落错。
这个 bug 只在 `hc_mult` 恰好等于 4 时不发作 —— 也就是开发时用的那个模型。

**怎么验证**：`configs.tsx` 里必须有 `hc_mult` 为 1 / 2 / 3 / 4 / 5 / 16 / 64 的配置。

### R6 每条线在自己对应的图层里，形成正确遮挡

叠片之间的连线不能全画在最上层。每条边声明归谁画
（`ownedBySource` / `ownedByTarget`）；两端都拥有时，在拐点处切成两半
（`EdgePart`），各画各的一半。

**怎么验证**：截图看，线不能横在任何叠片的正面上。

### R7 重复的算子画成 N 个大盒子重叠，不是一个大盒子里套小算子

`repeat` 个实例就是 `repeat` 个同样大小的盒子往后叠。一个大盒子里画几个小 op，
读起来像"这个算子内部有几个子算子"，意思完全不同。

**单个 repeat 也要有盒子**：`repeat: 1` 时曾经退化成一个裸 op，读者以为它是黑盒。
没有 `inner` 就合成一个。

**怎么验证**：截图看 `ffn hc_post`、`scale by pre`、`attn.wo_a`。

### R8 盒子里的算子不能挨太紧

`GROUP_DX` / `GROUP_DY` / `GROUP_PAD` 留够。发现一处就彻查同类，不要只修那一个。

**怎么验证**：`geom.tsx` 的 `walk` 会检查节点重叠与 band 内边距。

### R9 拐角必须在空挡里，且不得落在任何节点的水平跨度内

两条都由 `turnsInAGutter` 守住。拐在长途中间，会把横腿铺在它正要离开的那一行上
（fork 曾横跨 `hc_head`、`norm`、`lm_head`）；拐角落在节点跨度内，会被那个节点压住
（`BUNDLE_BEND` 超过 30px 空挡时，fork 的角躲到了 `hc_head` 底下）。

**怎么验证**：`check.tsx` 与 `configs.tsx` 都对每条边跑 `turnsInAGutter`；
反向验证方法是把拐点规则改回 `BUNDLE_BEND`，它应当报错。

### R10 首尾都要有张量

整个模型的输入要画成一个张量（token ids），不能让 embedding 成为唯一一个没有输入的
算子。层堆叠的输出也要画成张量，因为图里其它算子的输入都画了。

**推论（踩过的坑）**：那个张量必须是**真正流到那里**的张量。写成
`branch?.io ?? input` 时，MTP 打开才对，而 MTP 默认关闭，默认状态下画的是模型的
token ids。

**怎么验证**：`configs.tsx` 断言 `stackOut` 的形状等于喂给 stack 的形状。

### R11 同一个张量不能在切口两侧各画一次

展开某一层时，strip 在切口处剪开。切口之前由 strip 保留、块不画入口
（`omitEntry`）；切口之后由块保留、strip 那份被窗口裁掉（`omitExit`）。
规则只有一份实现：`lib/arch/splice.ts`，组件和断言都调它。

**怎么验证**：`check.tsx` 的"没有张量被画在切口两侧"断言。

### R12 被切掉的东西不能留下半截标签

chip 只有 11px 宽，名字居中就会探出左缘；切在 chip 左缘时那几个字母留在了左半边。
caption 从节点左缘起排，并且布局要为它预留过空间。

**怎么验证**：浏览器里扫一遍所有文字与自身节点框的关系，只允许预留过空间的
caption 向右外溢。

### R13 band 要盖住它里面所有东西，包括 caption

张量的 role caption 在盒子下方，band 的下内边距必须算进 `CAPTION_H`。
所有 padding 从布局自己的常量推导，不要另写数字。

**怎么验证**：`geom.tsx` 的 band 内边距检查。

### R14 水平对齐

同一条流水线上的节点中心线对齐。展开后，块的入口线要和 strip 的交接线对齐
（注意 `Layout.centre` 与 `Layout.exit` 不一定相同，MTP 块差 58px）。

**怎么验证**：截图看；量 DOM 里各节点中心 y。

### R20 未展开的层要在方框里写出它的层号

一排空白方框说不出哪个是哪层，而 tooltip 只回答指针底下那一个。方框里写
`L0`、`L1`……**零基，与 checkpoint 的 `layers.N` 一致** —— 图上写 L8 而文件里是
`layers.7`，等于让读者每次都做一次换算。

**方框宽度由最宽的标签算出，并且整排统一**（`chipWidth(layerCount)`）：
`L7` 在 128 层的模型里和 `L127` 一样宽。统一是必须的，因为切口是用 pitch
乘出来的，逐片不同宽就得改成累加。

**踩过的坑**：宽度原本是常量 `CHIP_W = 11`，被渲染、`splice`、断言三处各自
引用。改成随层数变化之后，任何一处漏改都会让切口落到错误的两片之间。所以宽度
挂在 `PlacedStack.chipW` 上，三处都读同一个数。

**同一个「L 几」只能有一份实现**：chip 里、tooltip 里、展开后表头的层号列表里，
全部走 `chipLabel()`。这三处曾各写一遍 `` `L${i}` ``。

**怎么验证**：`check.tsx` 断言每个切口都落在 chip 边界上，pitch 取自
`stack.chipW`；反向验证是把 `splice` 的 pitch 改回常量，它应当报
「layer 1 left cut at 782, chip edge at 793」。再截图看一眼层号是否可读
（最深的那档类型底色下也要清楚）。

### R21 一个算子读几个存储张量，就画几个

`weight` 只能表示一个。偏置、缩放、查找表都是 checkpoint 里独立的张量，有各自的
形状和 dtype —— 画一个、把其余写进句子里，等于这个 glyph 无法回溯。用
`ArchOp.extras` 补齐，它们在算子上方竖着摞起来，最靠近算子的是主权重。

**挂在哪个算子上，要按它作用在哪一步判断。** hyper-connection 的
`hc_*_base` / `hc_*_scale` 和 `hc_*_fn` 进的是同一个 kernel，但只有 `fn` 是逐副本的；
`base` 是一条和求和结果等宽的向量、`scale` 每个输出集一个，两者都作用在副本相加**之后**。
挂到逐副本的那个算子上，就等于宣称每个副本各有一份。

**有 `repeat` 的算子画成实例盒，外层的 `weight` / `extras` 不会被绘制** —— 盒内那份
才是画出来的。所以参数要挂在盒内真正持有它的那个算子上。

**间距要把说明文字算进去**：`WEIGHT_STEP = TENSOR_H + CAPTION_H + 8`。写成
`TENSOR_H + 12` 时，上一个参数的名字正好压在下一个盒的上沿。

**怎么验证**：`geom.tsx` 有一条「同一摞的存储参数不得相互重叠」的断言（权重节点被
行重叠检查显式跳过，所以必须单独守）；反向验证是把 `WEIGHT_STEP` 改回
`TENSOR_H + 12`，它应当报「overlap by 1」。另外跑 `tmp/check/gap.tsx`：
它把 checkpoint 的每一个张量和图上画出的权重名对账，应当输出「未绘制张量 0」。

### R22 checkpoint 里有的张量，要么画出来，要么写进 `omitted`

没有第三种状态。`gap.tsx` 就是这条规则的执行者 —— 它按归一化后的张量名做全量对账，
69,187 个张量一个都不许漏。

**这条规则抓到过一个事实错误，不只是遗漏。** 查「hash 层为什么存着一个没画的
`ffn.gate.weight`」时发现：vLLM 的 forward 无条件执行
`router_logits, _ = self.gate(hidden_states)`（nvidia/model.py:1057），再把 logits 和
哈希表一起喂给同一个路由 kernel。也就是说 hash 层**照样看 hidden state**，表只决定选
哪些专家、分数仍决定权重 —— 而图上那句注记写的是「the hidden state is not consulted」。

所以「还有什么没画」这个问题要定期机械地问一遍，它查出来的不止是缺口。

### R23 权重对账为零，不等于画全了

`gap.tsx` 只能看见**有存储张量**的东西。没有权重的算子——RoPE、逆 RoPE、加法、
量化——它一个也看不见。所以对账清零之后，还要把图上的算子序列和实现的 forward
逐条对一遍。

这一轮对 DeepSeek-V4 做这件事，在权重已经零缺口的情况下又查出 6 处：

| 类型 | 内容 |
| --- | --- |
| 画错 | shared expert 与 routed **并行**读同一个 hidden state、结果相加（`nvidia/model.py:1123-1124`），图上却画成串在 routed 之后 |
| 漏画 | 输出投影前的逆 RoPE（`o_proj.py:44-58`） |
| 漏画 | compressor 里的 RoPE —— kernel 名就叫 `compress_norm_rope_store_triton` |
| 漏画 | indexer q 的 RoPE（`attention.py:1085-1093`） |
| 漏画 | indexer 自带 compressor 的 RoPE（同一个类，同样收 `positions, rotary_emb`） |
| 漏画 | `positions`，模型的第二个输入 |

**这个架构有五处 RoPE，原来只画了两处。**

**怎么验证**：`tmp/check/ops.tsx` 打印每一段的算子序列，拿它对着实现的 forward 读。
算子序列是人工比对，没有捷径 —— 但把它打印出来，比在几千行 TSX 里回忆可靠。

### R24 同一个输入被很多算子读时，可以只在注记里说

`positions` 被五处 RoPE 读。老实画成张量，就是五条跨越整张图的线，去说一件
「RoPE 读位置」这种每个读者都知道的事，主干会被淹掉。

所以：**不画线，在每个 RoPE 的注记里写 `by position`，并把这个取舍写进 `omitted`。**
省略必须是一句明确的话（R22），不能只是没画。

这条只适用于「广播式的次要输入」。主干上流动的张量一律照画 —— 判据是：去掉这条线，
读者会不会对**数据怎么流**产生误解。位置不会，隐藏状态会。

### R25 依赖不是直线的，要写出来

`ArchStep` 只有 `out`，所以一条链就是一条线：每一步吃上一步的产出。这个架构里**大量
依赖不在这条线上**，而契约没法表达时，布局就把它们接到了错的地方。

两个字段：

- **`uses: string[]`** —— 这一步还读哪些别处产出的张量（按 `label` 引用，就近的那个）。
  被 `uses` 认领的张量**不再自动接到下一段**，假边就是这么消失的。
- **`detached: true`** —— 这一步**不读**上一步的产出，`uses` 就是它的全部输入。

画成一条走在内容下方的回程轨：在源后面的空挡里下来、沿轨横穿、在目标前面的空挡里上去。
两个拐角都在空挡里，所以 R9 照常成立。

**一个实例盒会吞掉依赖声明**：`instance()` 重建 step 时要把被它包住的那些 step 的
`uses` 并上来（盒外的张量是**盒**在读），而盒内的那份要丢掉（那个张量在盒外）。
少了这一步，重复算子的依赖会全部消失 —— 而这个架构大半的算子都是重复的。

**怎么验证**：`uses` 指向不存在的张量时布局直接抛错；strip 不支持回程轨，遇到
`uses`/`detached` 也抛错，而不是静默忽略。

### R26 用形状抓假边

自动接的那条边没人声明，所以也没人检查 —— **所有假边都出在这里**。但它们在数字上
藏不住：

- 线性映射写明了它消费多宽（`inDim`）
- norm 与 elementwise 保持最后一根轴

于是一条断言就能抓：**每条自动边，源张量的最后一维必须对得上目标**。`uses` 边不查，
那是有人特意写下的依赖，形状本来就可以不同。

这条规则一次抓出 7 处假边，其中 3 处是我当轮刚写进去的：

| 假边 | 真相 |
| --- | --- |
| `pre post comb → attn_norm` | norm 只吃求和后的 hidden |
| `index q → indexer.weights` | `weights_proj` 是 `[heads, dim]`，读 hidden |
| `hidden → indexer.wq_b` | 读的是 Q latent —— 注记早写着「reuses the Q latent」 |
| `compressed kv → compressor.wgate` | wkv 与 wgate 是对 hidden 的两个投影，实现里还被融合成一个 GEMM |
| `index kv → indexer.compressor.wgate` | 同上 |
| `scale → hc_*_fn` | 投影读的是那份副本，不是标量因子 |
| `expert ids + weights → routed expert` | 专家读 hidden，路由只决定选谁、权重多少 |

**盲区就是漏洞**：这条断言最初跳过了实例盒（重复算子），于是只有 `o_groups: 1` 那种
配置才暴露问题。堵上盲区，立刻又抓到「专家读路由结果」这一条。**写断言时，凡是
`continue` 掉的分支都要问一句：那里是不是正好藏着最多的东西。**

### R27 「还缺什么」要能一条命令答完

不要再靠一轮轮地问。维度先列全，能机械化的全部机械化：

```sh
sh tmp/check/complete.sh
```

| # | 维度 | 手段 |
| --- | --- | --- |
| 1 | 存储张量 | `gap.tsx`，对 checkpoint 全量对账 |
| 2 | 依赖边 | R26 的形状断言 + 「产出必被读取」 |
| 3 | 几何 | `check.tsx` |
| 4 | 配置健壮性 | `configs.tsx` |
| 5 | 文案 | `labels.tsx` |
| 6 | 算子序列 | `ops.tsx` 打印，人工对 forward |

只有第 6 项还得靠人。**一个维度不列出来，它就会在下一次被问到时才冒出来** —— 这正是
这张图被问了三轮、每轮都掉出一层新问题的原因。

## 交互

### R15 展开在原地把两边推开，不另开界面

点开一层是把 strip 从那一层剪开、把两半推开、在中间插入细节图，细节图可横向滚动。
不是切换到另一个视图。

### R16 动画要丝滑，且不能只靠 CSS 过渡

`UNFOLD_MS` / `UNFOLD_EASE` 固定。整层有面板宽度的十倍，一次动完读起来是跳变，
所以只动一屏，其余在动画结束后一步走完（那时右半边已经在屏幕外）。

**踩过的坑**：`requestAnimationFrame` 和 CSS 过渡在未绘制的标签页里不推进，
于是面板停在零宽、`transitionend` 永不触发、Close 按钮失效。每一处都要有定时器兜底
（`soon()`）。

**怎么验证**：在后台标签页里打开再切回来，展开与收起都要能完成。

### R17 双击收起，且 Close 要显眼

收起动画与展开对称。

### R18 展开后下方不留大片空白

用显式偏移，不要用对称 gap 硬凑。曾经在下方留了 92px 空白。

### R19 图例行、"Not drawn" 行不画在图上

没画的东西写进 `omitted`，它作为 tooltip 出现。图面上不放解释性行。

## 怎么加新规则

1. 规则来自一次真实返工 —— 抽象的偏好不进这个文件。
2. 三段写全：规则、为什么（或"踩过的坑"）、怎么验证。
3. 能用断言守住的，同时在 `tmp/check/` 里加断言，并**反向验证**
   （故意改坏代码，确认它报错）。
4. 编号只递增，不复用、不重排。
